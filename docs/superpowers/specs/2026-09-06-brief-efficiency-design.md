# 브리핑 전 채널 수집 + 토큰 효율화 설계

작성일: 2026-09-06
상태: 승인됨 (구현 계획 작성 대기)
선행 설계: `2026-09-06-market-briefing-agent-design.md`

## 배경

온디맨드 브리핑 파이프라인(`/brief`)을 1회 완주한 뒤 세 가지 요구가 나왔다.

1. 화이트리스트 대신 구독 중인 텔레그램 채널 전체를 대상으로 할 것
2. Sonnet 5 로도 같은 품질의 보고서가 나오도록, 적은 토큰으로 동일 업무를 수행할 것
3. 불필요한 문구를 걷어낼 것

## 결정 사항

### 1. 전 채널 수집

`is_channel and not is_group` (브로드캐스트만) 전수 수집. 그룹과 1:1 대화는 구조적으로
제외되므로 개인 대화가 수집될 여지가 없다.

`channels.py` 를 화이트리스트에서 **제외 목록**으로 뒤집는다(기본값 비어 있음).
`channel_match.py` 는 해석할 제목이 없어지므로 제거한다.

**카테고리 힌트 맵은 만들지 않는다.** 채널 이름이 이미 자기 설명적이고
(`[하나증권 해외채권] 허성우`), 힌트 맵은 채널명이 바뀔 때마다 드리프트하는
관리 대상이 하나 더 늘어날 뿐이다.

**채널 분류 어휘가 바뀐다.** 화이트리스트가 없으면 "미가입"이라는 개념 자체가
성립하지 않는다. 매니페스트와 인덱스의 필드를 아래로 재정의하고, 대시보드 하단의
`미가입: …` 줄을 제거한다.

| 기존 | 이후 | 의미 |
|---|---|---|
| `matched` | `collected` | 이번 실행에서 실제로 조회한 채널 |
| `missing` | `excluded` | 제외 목록에 걸려 건너뛴 채널 |
| `not_checked` | `not_checked` | 요청 제한으로 조회하지 못한 채널 (유지) |
| `quiet_channels` | `quiet_channels` | 조회했으나 오늘 새 글이 없는 채널 (유지) |
| `unsubscribed_channels` | 제거 | 개념 소멸 |

이 전환은 화이트리스트 드리프트 문제도 함께 해소한다. 미매칭의 실제 원인은
구독 누락이 아니라 제목 전사 오류였다.

| 화이트리스트 | 실제 제목 |
|---|---|
| 하나증권 리서치 중국/신흥국 전략 김경환 | 하나 중국/신흥국 전략 김경환 |
| DAOL 시황 김지현 & 경제/전략 조병현 | [다올 매크로/투자전략] 조병현/박영찬/정현하/홍록은 |
| KB 채권 임재균 박준우 박문현 | KB 채권 - 임재균 & 박문현🙂 |
| 미래에셋증권 금융 정태준 | 한국투자증권 금융 정태준 (소속이 다름) |

### 2. 토큰 효율화

레버를 실측 영향 순으로 적용한다.

| 레버 | 조치 | 기대 효과 |
|---|---|---|
| 노이즈 | 파이썬 필터로 광고성·저신호·채널 내 근사중복 제거 | 하류 전 단계 비례 축소, LLM 비용 0 |
| 렌더 | 대시보드를 커밋된 템플릿 + JSON payload 주입으로 전환 | 출력 약 10K → 2K 토큰 |
| 클러스터링 입력 | 파이썬이 전용 경량 뷰 생성, 헤드라인 120→70자 | 약 50% |
| 섹션 입력 | 토픽별 원문 슬라이스를 파이썬이 사전 추출 | 에이전트당 read/grep 턴 제거 |
| 시세 | TTL 캐시 | 같은 날 반복 호출분 |

**Sonnet 품질 유지의 핵심은 렌더 항목이다.** 현재는 모델이 매 실행마다 레이아웃을
다시 만들어내므로 모델이 바뀌면 결과물이 흔들린다. 템플릿을 고정하면 모델은 내용만
채우고 레이아웃은 상수가 된다.

### 3. 뷰 레이어 — HTML 템플릿 + 바닐라 데이터 주도 렌더

React 를 쓰지 않는다.

payload 설계에서 모델은 마크업을 쓰지 않고 JSON 만 쓰므로, 템플릿 내부가 React 든
바닐라든 **실행당 토큰 비용이 같다**. React 는 얻는 것 없이 비용만 더한다 — cdnjs 에서
React + ReactDOM UMD 를 먼저 로드해야 하고, JSX 를 쓰려면 빌드 단계나 Babel standalone
(1.5MB, 브라우저 내 컴파일)이 필요하며, 빌드 없이 쓰면 `React.createElement` 호출이
되어 한국어 텍스트 위주 보고서에서는 HTML 보다 쓰기도 읽기도 나빠진다.

"React 가 유리하다"는 지적의 실질은 **반복 구조를 복붙하지 말고 데이터로 돌리라**는
것이고, 그 이득은 payload 설계로 이미 확보된다. 바닐라 렌더 함수로 충분하다.

**재검토 조건**: 채널별 필터, 병합 섹션 토글, 과거 브리핑 날짜 이동 등 **상태**가
생기면 그때 React 도입을 재검토한다.

## 데이터 계약

렌더 단계의 입출력을 고정한다. 모델은 아래 payload 만 생성한다.

```json
{
  "date": "2026-09-06",
  "collected_at": "18:13 KST",
  "channel_count": 9,
  "message_count": 171,
  "filtered_out": {"advertorial": 63, "low_signal": 0, "near_duplicate": 2},
  "indicators": [
    {"name": "KOSPI", "label": "코스피", "last": 6687.21, "change_pct": 1.64,
     "as_of": "2026-09-04", "spark": null, "note": "추이 데이터 신뢰 불가"}
  ],
  "topics": [
    {"topic_id": "t1", "title": "...", "primary_channel": "...",
     "merged": [{"channel": "...", "what": "유조선 타격 건"}],
     "organized": "...", "summary": "...",
     "indicators": [{"label": "VIX", "value": "14.53", "change": "+1.47%"}],
     "draft_insight": "...",
     "sources": [{"type": "telegram", "channel": "...", "time": "22:39"}]}
  ],
  "quiet_channels": ["..."],
  "not_checked_channels": ["..."],
  "excluded_note": "한국경제 채널의 협찬성 제품 기사 63건 제외"
}
```

템플릿(`market-briefing/templates/dashboard.html`)은 이 payload 를 인라인 `<script>`
한 줄로 받아 렌더한다. 레이아웃·색·타이포는 템플릿에 고정되어 실행마다 변하지 않는다.

## 노이즈 필터 규칙

세 가지만 둔다. 규칙이 늘어나면 유지보수가 필터의 이득을 잠식한다.

1. **협찬성 제품 기사** — 아래를 모두 만족하는 항목. 한국경제 코퍼스에서 관찰된 형태로,
   구현자가 판단할 여지를 남기지 않도록 기계적 조건으로 못박는다.
   - 본문이 한 줄이고 120자 미만
   - 첫 줄이 `<8자 이내 명사>, ` 또는 `<8자 이내 명사>… ` 로 시작 (브랜드명 + 쉼표)
   - 숫자·티커·URL 이 없거나, URL 이 있어도 그 줄이 위 형태를 만족
   예: `무아스, 감성·편의성 다 갖춘 프리미엄 생활용품` / `정로환, 캠핑·출장 때도 마음 놓이는 '국민 지사제'`
   반례(제외하면 안 됨): `무디스는 "9년 만에 재정흑자…韓 신용도에 우호적"`(숫자 포함),
   `수출 작년 실적 벌써 넘었다…사상 첫 '1조 달러' 코앞`(쉼표 형태 아님)
2. **저신호** — 본문 20자 미만이면서 URL·숫자·티커가 모두 없는 항목
   (`??????`, `위켄드 나스닥도 잘 버티는중` 같은 단문).
3. **채널 내 근사중복** — 같은 채널에서 조간·석간으로 반복된 항목
   (`수출 1조 달러`, `LG 로봇관절`이 같은 날 두 번 등장).

필터는 삭제가 아니라 **표시**다. 제외된 항목 수를 payload 에 담아 대시보드 하단에
"몇 건을 왜 뺐는지" 남긴다. 근거 없이 사라지는 정보가 없어야 한다.
